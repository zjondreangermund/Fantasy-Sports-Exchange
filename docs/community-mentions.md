# Community tagging and notification links

Typing `@` opens up to eight suggestions. Partial public team/display names also suggest matching tags without requiring the spelling of the complete team name. Select with touch/click, arrows and Enter/Tab; Escape closes the suggestions. Enter selects an active suggestion before sending, Shift+Enter adds a newline, and edits support the same suggestions. Insertion respects the cursor and 280-character limit.

The authenticated, rate-limited suggestions endpoint returns only the public team/display name, text handle and an ambiguity flag. It excludes the current account, banned accounts and unnamed email-only accounts. Email addresses, private names behind an existing public team name, account IDs and admin data are not returned. Ambiguous normalized handles cannot be selected; existing server mention-recipient guards suppress ambiguous manual tags as well. Mention parsing uses complete 2–30-character tags rather than accepting the prefix of an overlong tag.

Web, native Android and inbox destinations carry the community message ID and notification ID in `/dashboard?community=1&communityMessage=...&notification=...`. Android’s existing Capacitor notification action listener opens this same-origin app route, including retained cold-start notification actions. The service worker opens/focuses the web app at the same route. Legacy `/community` notifications are normalized and their inbox record resolves the message when available.

The root app captures only numeric community intent IDs before sign-in. A session-scoped intent survives ordinary sign-in redirects and is consumed once when the signed-in Community widget mounts. Warm in-app navigation and browser back/forward are also handled. Opening a mention switches to Community, fetches an uncached target message if necessary and scrolls/highlights it instead of following newer messages. Expired/removed messages leave Community open with an explanatory notice; 24-hour retention is unchanged. Assistant/member/admin conversations remain separate and are never posted to Community.

`npm run test:assistant` includes PostgreSQL-compatible directory tests, cursor/tag tests, exact production native/web destination-function checks, service-worker cold/warm click tests, external destination rejection and sign-in intent recovery tests. These checks do not send real notifications or claim end-to-end verification on a physical device. Notification permission and a registered app/browser subscription remain necessary for push delivery.
